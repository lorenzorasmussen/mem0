# Mem0 Ecosystem Components

## Overview

Beyond the core library, Mem0 provides several ecosystem components for different deployment scenarios and user experiences:

1. **OpenMemory** - Local vector database deployments with UI
2. **Mem0 Online Platform** - Cloud-hosted memory management
3. **Chrome Extension** - Browser-based memory integration

## OpenMemory: Local Vector Database Deployments

OpenMemory provides a complete local memory infrastructure with support for multiple vector databases and a web-based management interface.

### Supported Vector Databases

OpenMemory supports 9 different vector database backends through Docker Compose configurations:

#### 1. **Qdrant** (Recommended - Default)
```yaml
# docker-compose.yml configuration
services:
  mem0_store:
    image: qdrant/qdrant:latest
    ports:
      - "6333:6333"
    volumes:
      - mem0_storage:/mem0/storage
```

**Configuration:**
```bash
# api/.env
QDRANT_HOST=localhost
QDRANT_PORT=6333
VECTOR_STORE_PROVIDER=qdrant
```

**Features:** High-performance, ACID transactions, REST API, good for production.

#### 2. **ChromaDB**
```yaml
services:
  mem0_store:
    image: ghcr.io/chroma-core/chroma:latest
    environment:
      - CHROMA_SERVER_HOST=0.0.0.0
      - CHROMA_SERVER_HTTP_PORT=8000
    ports:
      - "8000:8000"
    volumes:
      - mem0_storage:/data
```

**Configuration:**
```bash
CHROMA_HOST=localhost
CHROMA_PORT=8000
VECTOR_STORE_PROVIDER=chroma
```

**Features:** Simple, Python-native, good for development.

#### 3. **Weaviate**
```yaml
services:
  mem0_store:
    image: semitechnologies/weaviate:latest
    environment:
      - QUERY_DEFAULTS_LIMIT=25
      - AUTHENTICATION_ANONYMOUS_ACCESS_ENABLED=true
      - PERSISTENCE_DATA_PATH='/var/lib/weaviate'
    ports:
      - "8080:8080"
    volumes:
      - mem0_storage:/var/lib/weaviate
```

**Configuration:**
```bash
WEAVIATE_URL=http://localhost:8080
VECTOR_STORE_PROVIDER=weaviate
```

**Features:** GraphQL API, semantic search, multi-modal support.

#### 4. **Milvus**
```yaml
services:
  mem0_store:
    image: milvusdb/milvus:latest
    environment:
      - ETCD_ENDPOINTS=localhost:2379
      - MINIO_ADDRESS=localhost:9000
    ports:
      - "19530:19530"
      - "9091:9091"
    volumes:
      - mem0_storage:/var/lib/milvus
```

**Configuration:**
```bash
MILVUS_HOST=localhost
MILVUS_PORT=19530
VECTOR_STORE_PROVIDER=milvus
```

**Features:** High scalability, distributed architecture.

#### 5. **Pinecone** (Cloud)
**Configuration:**
```bash
PINECONE_API_KEY=your_api_key
PINECONE_INDEX_NAME=mem0
VECTOR_STORE_PROVIDER=pinecone
```

**Features:** Managed cloud service, global CDN, automatic scaling.

#### 6. **Redis**
```yaml
services:
  mem0_store:
    image: redis/redis-stack:latest
    ports:
      - "6379:6379"
      - "8001:8001"
    volumes:
      - mem0_storage:/data
```

**Configuration:**
```bash
REDIS_URL=redis://localhost:6379
VECTOR_STORE_PROVIDER=redis
```

**Features:** In-memory storage, fast access, Redis Stack includes search.

#### 7. **PostgreSQL with PGVector**
```yaml
services:
  mem0_store:
    image: pgvector/pgvector:pg16
    environment:
      - POSTGRES_DB=mem0
      - POSTGRES_USER=mem0
      - POSTGRES_PASSWORD=password
    ports:
      - "5432:5432"
    volumes:
      - mem0_storage:/var/lib/postgresql/data
```

**Configuration:**
```bash
PGVECTOR_HOST=localhost
PGVECTOR_PORT=5432
PGVECTOR_USER=mem0
PGVECTOR_PASSWORD=password
PGVECTOR_DATABASE=mem0
VECTOR_STORE_PROVIDER=pgvector
```

**Features:** ACID compliance, SQL queries, mature ecosystem.

#### 8. **Elasticsearch**
```yaml
services:
  mem0_store:
    image: elasticsearch:8.11.0
    environment:
      - discovery.type=single-node
      - xpack.security.enabled=false
      - "ES_JAVA_OPTS=-Xms512m -Xmx512m"
    ports:
      - "9200:9200"
    volumes:
      - mem0_storage:/usr/share/elasticsearch/data
```

**Configuration:**
```bash
ELASTICSEARCH_HOST=localhost
ELASTICSEARCH_PORT=9200
VECTOR_STORE_PROVIDER=elasticsearch
```

**Features:** Full-text search, aggregations, Kibana integration.

#### 9. **OpenSearch**
```yaml
services:
  mem0_store:
    image: opensearchproject/opensearch:latest
    environment:
      - discovery.type=single-node
      - "ES_JAVA_OPTS=-Xms512m -Xmx512m"
    ports:
      - "9200:9200"
    volumes:
      - mem0_storage:/usr/share/opensearch/data
```

**Configuration:**
```bash
OPENSEARCH_HOST=localhost
OPENSEARCH_PORT=9200
VECTOR_STORE_PROVIDER=opensearch
```

**Features:** Open-source Elasticsearch fork, community-driven.

### OpenMemory Setup

1. **Clone and Setup**:
   ```bash
   cd openmemory
   cp api/.env.example api/.env
   cp ui/.env.example ui/.env
   ```

2. **Configure Environment**:
   ```bash
   # api/.env
   OPENAI_API_KEY=your_openai_key
   USER_ID=your_user_id
   
   # ui/.env  
   NEXT_PUBLIC_API_URL=http://localhost:8765
   NEXT_PUBLIC_USER_ID=your_user_id
   ```

3. **Build and Run**:
   ```bash
   make build  # Builds MCP server and UI
   make up     # Runs OpenMemory MCP server and UI
   ```

4. **Access Interfaces**:
   - **MCP Server**: http://localhost:8765 (API docs at /docs)
   - **Web UI**: http://localhost:3000
   - **Health Check**: http://localhost:8765/health

- **Multi-Vector DB Support**: Choose your preferred vector database

- **User Isolation**: Separate memory spaces per user

- **Docker-Based**: Easy deployment and scaling

## Mem0 Online Platform Integration

The Mem0 cloud platform provides managed memory services with advanced features and global scalability.

### Platform Features

- **Managed Infrastructure**: No server maintenance required
- **Global CDN**: Low-latency access worldwide
- **Advanced Analytics**: Memory usage and performance metrics
- **Team Collaboration**: Shared memory spaces
- **API Rate Limiting**: Built-in protection
- **Backup & Recovery**: Automatic data protection

### Getting Started with Cloud API

1. **Sign Up**:
   - Visit [app.mem0.ai](https://app.mem0.ai)
   - Create account and get API key

2. **API Key Setup**:
   ```bash
   export MEM0_API_KEY=your_api_key_from_dashboard
   ```

3. **Python Integration**:
   ```python
   from mem0 import MemoryClient
   
   client = MemoryClient(api_key='your_api_key')
   
   # Add memory
   client.add('Important information', user_id='user123')
   
   # Search memories
   results = client.search('important', user_id='user123')
   ```

4. **REST API Usage**:
   ```bash
   # Add memory
   curl -X POST 'https://api.mem0.ai/v1/memories/' \
     -H 'Authorization: Token your_api_key' \
     -H 'Content-Type: application/json' \
     -d '{"messages": [{"role": "user", "content": "Hello"}], "user_id": "user123"}'
   
   # Search memories
   curl 'https://api.mem0.ai/v1/memories/?query=hello&user_id=user123' \
     -H 'Authorization: Token your_api_key'
   ```

## Migration Between Components

### Data Export/Import Tools

#### OpenMemory Backup Scripts
Located in `openmemory/backup-scripts/`:
- `export_openmemory.sh`: Export all memories to JSON
- Supports incremental backups
- Includes metadata and user information

#### Platform API Endpoints
- **Export**: `GET /v1/memories/export`
- **Batch Import**: `POST /v1/memories/batch`
- **Incremental Sync**: Webhook-based synchronization

### Migration Paths

#### 1. Local OpenMemory → Mem0 Platform
```bash
# Export from OpenMemory
cd openmemory/backup-scripts
./export_openmemory.sh

# Import to Mem0 Platform
curl -X POST 'https://api.mem0.ai/v1/memories/batch' \
  -H 'Authorization: Token your_api_key' \
  -H 'Content-Type: application/json' \
  -d @exported_memories.json
```

#### 2. Mem0 Platform → Local OpenMemory
```bash
# Export from platform
curl 'https://api.mem0.ai/v1/memories/export?user_id=your_user' \
  -H 'Authorization: Token your_api_key' > memories.json

# Import to OpenMemory
curl -X POST 'http://localhost:8765/memories/batch' \
  -H 'Content-Type: application/json' \
  -d @memories.json
```

#### 3. Library-based → Any Platform
```python
# Export from library
from mem0 import Memory
memory = Memory.from_config(your_config)
all_memories = memory.get_all(user_id='user123')

# Import via API
import requests
response = requests.post(
    'https://api.mem0.ai/v1/memories/batch',
    headers={'Authorization': f'Token {api_key}'},
    json=all_memories
)
```

#### 4. Chrome Extension → Platform
Extension automatically syncs with Mem0 Platform when API key is configured. No manual migration needed.

### Migration Considerations

#### Data Compatibility
- **Metadata Preservation**: All custom fields and tags maintained
- **User Isolation**: User-specific data properly segregated
- **Timestamps**: Creation and update times preserved

#### Feature Mapping
- **Search Filters**: Tag-based filtering supported across all platforms
- **Memory Types**: Factual, procedural, semantic memories maintained
- **Relationships**: Memory connections preserved where supported

#### Performance Considerations
- **Batch Size**: Use appropriate batch sizes for large migrations
- **Rate Limiting**: Respect API rate limits during migration
- **Downtime**: Plan for minimal service interruption

#### Validation Steps
1. Export data from source system
2. Validate export integrity (count, metadata)
3. Import to target system
4. Verify import success (count, search functionality)
5. Test application integration
6. Monitor for 24-48 hours post-migration
